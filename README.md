# LogSentry

Анализатор **логов веб-сервера** (Apache/Nginx, формат combined) — мини-SIEM в одном файле. За секунды превращает гигабайтный access-лог в отчёт: распределение HTTP-кодов, топ адресов и страниц, почасовая нагрузка и автоматическая детекция подозрительной активности (brute-force, сканеры).

Никаких зависимостей и баз: нужен только JDK и сам лог-файл.

## Идея проекта

Малая компания обычно узнаёт об атаке постфактум, потому что платный SIEM не по карману, а читать логи глазами невозможно. LogSentry закрывает первый уровень защиты: один запуск по свежему логу отвечает на три вопроса — **что происходило** (коды, URL), **кто приходил** (топ IP) и **кого стоит заблокировать** (подозрительные IP).

| Отчёт | Что даёт |
|---|---|
| Классы HTTP-кодов | здоровье сервиса: рост 5xx — проблема в приложении, рост 4xx — сканирование |
| Топ-5 URL | что реально запрашивают (и что перебирают боты) |
| Топ-5 IP | основные клиенты и основные нарушители |
| Подозрительные IP | кандидаты в fail2ban/файрвол |
| Гистограмма по часам | пиковая нагрузка и ночная аномальная активность |

## Быстрый старт

Нужен **JDK 17 или новее**. Проверить: `java -version`.

```bash
git clone https://github.com/KorolKiraA/log-sentry.git
cd log-sentry

java LogSentry.java /var/log/nginx/access.log   # свой лог
java LogSentry.java                              # встроенный демо-лог
```

Без аргумента программа разбирает встроенный демо-лог из 15 строк с одной «атакой» — удобно проверить работу без реальных данных.

## Что получится на выходе

Реальный вывод на демо-логе (сокращённо):

```
Строк в файле: 15, распознано: 15

--- HTTP-коды ---
  2xx: 7 (46,7%)
  4xx: 6 (40,0%)
  5xx: 2 (13,3%)

--- Топ-5 IP ---
       5  203.0.113.77
       3  192.168.1.10

--- Подозрительные IP (доля 4xx/5xx > 50%) ---
  ⚠ 203.0.113.77: 5 запросов, 5 ошибок (100%)

--- Запросов по часам ---
  09:00 | █████████████ 2
  10:00 | ████████████████████████████████████████ 6
  11:00 | █████████████ 2
```

IP `203.0.113.77` четырежды получил `401` на `/api/login`, а затем полез в `/admin` — классический перебор паролей. Программа помечает его флагом `⚠`.

## Правило детекции

IP считается подозрительным, если выполнены **оба** условия:

1. больше 3 запросов (отсекаем случайные ошибки обычных пользователей);
2. доля ответов 4xx/5xx строго больше 50%.

Пороги вынесены в код рядом с отчётом и легко подстраиваются: например, для API-шлюза, где 401 — норма, долю стоит поднять до 80%.

## Как это устроено

```
log-sentry/
├── LogSentry.java        # парсер, статистика, детекция, отчёты
├── .github/workflows/ci.yml  # компиляция на каждый push
├── LICENSE
└── README.md
```

**Ключевые решения в коде:**

- одна регулярка на формат combined: `IP — метод, URL, статус`; строки, которые не распарсились, не роняют анализ, а просто не учитываются (их видно по разнице «строк в файле / распознано»);
- вся статистика — `Stream API` с `Collectors.groupingBy`, топ-N через сортировку по значению;
- `record Entry` — неизменяемая запись одной строки лога;
- гистограмма строится делением на максимум: самый загруженный час всегда ровно 40 символов.

## Проектные решения и ограничения

- **Файл читается целиком в память** (`Files.readAllLines`). Для логов до нескольких сотен мегабайт это нормально; для гигабайтных нужен потоковый проход `Files.lines`.
- **Только формат combined.** JSON-логи (nginx `log_format json`) потребуют другого парсера.
- **Детекция по эвристике**, а не по сигнатурам: ложные срабатывания возможны на API с частыми 401. Это осознанный компромисс первого уровня защиты, а не замена полноценного SIEM.
- **Время берётся из строки лога как есть** — без учёта часовых поясов.

## Частые проблемы

| Проблема | Решение |
|---|---|
| `Распознано: 0` | формат лога не combined — проверьте первую строку файла; под другой формат нужно поправить регулярку `LINE` |
| Крякозябры вместо кириллицы в `cmd` | `chcp 65001` и `java -Dfile.encoding=UTF-8 LogSentry.java access.log` |
| `java: команда не найдена` | `winget install Microsoft.OpenJDK.17`, затем переоткрыть терминал |
| Лог на удалённом сервере | скопируйте локально (`scp server:/var/log/nginx/access.log .`) — сетевой доступ программе не нужен |

## Идеи для развития

- потоковая обработка больших файлов (`Files.lines`) и инкрементальная статистика;
- геолокация IP (MaxMind GeoLite2) в отчёте по странам;
- детекция новых паттернов: перебор директорий, SQL-инъекции в URL, сканеры по User-Agent;
- экспорт отчёта в JSON/HTML для отправки на почту;
- режим слежения `tail -f` с алертами в реальном времени.
